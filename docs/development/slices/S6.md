# S6 — Time tracking

**Depends on:** S5
**State:** done

**Amends the plan:**

- **One running timer per person per organization**, not per person across the
  installation. Row-level security means one organization cannot see, and so cannot
  stop, a timer in another; a global index would refuse a timer for a reason nobody
  could inspect.
- **Person and organization default rates** did not exist before S6. They live in
  `default_rates`: one row per person (or the organization, with no user) per
  currency. A default applies only to projects in its currency. Time logged on a
  project in a currency with no defaults has no rate unless the project sets one,
  and is reported as unrated rather than as zero.
- **Billable and cost rates resolve independently.** A project override that sets
  only a billable rate still takes cost from the person's default. Each entry
  records the source of each rate.
- **Moving an entry to another project resolves its rates again**, at the rates in
  force when it moves. Every other edit keeps the rates the entry was logged at.
- **A project's currency is fixed once time is logged**, because entries and member
  rates are in it.
- **A task with time logged cannot be deleted** (`task_has_time`), only cancelled.
  The foreign key is not cascaded, so the database refuses too.
- **Permissions.** `timeEntryAll` gained `manage`, for logging, correcting, stopping,
  or deleting other people's time (managers). A new `rate:update` sets default
  rates (managers and finance), and also requires `report:readFinancial`.
- **Starting a timer stops the running one** rather than refusing, because a person
  has one clock. A start that races another fails with 409 `Conflict`.
- **Durations are whole seconds on the API** (`durationSeconds`). The UI accepts
  "1:30", "1.5", or "90m". One manual entry is at least a minute and at most 24 hours.
- **The timesheet week runs Monday to Sunday.** Days are calendar dates in the
  organization's time zone. A timer counts towards the day it started.

## Scope

In:
- Timers: start, stop (one's own, or anyone's with `timeEntryAll:manage`),
  correcting a running timer's start, and a running timer in the header on every page.
- Manual entries against a project or task, billable or not. Client projects
  default to billable; internal projects do not.
- Rate resolution and snapshotting; default rates per organization and person
  (Settings → Rates).
- The weekly timesheet (`/time`), with a person picker for those who can see
  everyone's time.
- The project's Time tab: tracked, billable, value, and cost; by person and by task
  against estimates; recent entries. The task page's Time card.
- Events: `time_entry.created`, `started`, `stopped`, `updated`, `deleted`, without
  rates.

Out:
- Approving or locking timesheets (Phase 2). Locking invoiced time arrives with
  invoices (S7b).
- Converting rates between currencies (S8, if at all).
- Rounding increments such as six-minute billing (S7b, when time becomes invoice lines).
- Idle detection and reminders for forgotten timers (Phase 2).

## Notes for later slices

- **S7b invoices** will turn billable entries into lines. They should copy the
  entry's own `billable_rate_minor`, never resolve a rate again, and mark the entry
  invoiced so that `timeEntry.update` and `delete` can refuse it.
- **S8 profitability** can read `time_entries` directly: value is
  `round(duration_seconds × rate ÷ 3600)` per entry, as in `timeEntry.summary`.
  Entries are in their project's currency, which cannot change once time exists.
- **An S5 bug, fixed here:** `queryFlag.optional()` still applied its default,
  so omitting `clientVisible` from `task.update`, `milestone.update`, or
  `comment.update` reset it to `false`. It silently unpublished records, and refused
  an author editing their own published comment. `optionalFlag` replaces it, with a
  regression test in `projects.test.ts`.
- **Fixed along the way (earlier slices):** the project Team tab and the header navigation
  widened the page on phones. The shared `Table` container is now `relative`, and
  the navigation shrinks inside its row. All 21 app pages were measured at 400px.
- **`TextField` and `SelectField` take an optional `id`.** Use it when one page holds
  two forms with the same field names, as the timesheet does.
- **Build with `NODE_ENV=production`.** `.env` sets `development`; loading it into
  the shell before `next build` fails the prerender of `/_global-error` with
  "Cannot read properties of null (reading 'useContext')".
