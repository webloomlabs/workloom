# S5 — Projects, milestones, tasks

**Depends on:** S1, S3
**State:** done

**Amends the plan:**

- **Task discussion and project updates share one `comments` table.** A comment with
  no task is an update on the project. A client-visible project update is what the
  portal will show.
- **A `comment` permission was added** (`create`, `moderate`). Account managers and
  finance need to discuss work they cannot edit, and a key scoped to `project:read`
  must not be able to write. Everyone can edit their own comments; `moderate` covers
  other people's.
- **Budgets and member rates are financial.** Reading or setting them requires
  `report:readFinancial`. Rates are left out of events entirely.
- **Dependencies stay within one project.** The schema enforces it: both of a
  dependency's foreign keys include `project_id`. A task cannot be completed while
  anything it waits on is open.
- **Member rates are in the project's currency** and override the person's defaults.
  S6 resolves and snapshots them. S8 may need to convert them into the base currency.
- **The context gained `afterCommit` and `afterRollback`.** Stored files must be deleted
  only once a deletion commits, and an upload must be removed if its transaction rolls
  back. This is how S7's emails should be sent too.
- **Uploads use `multipart/form-data`** through the same registry. An `http.body:
  'multipart'` binding makes the API parse form fields and files into the procedure's
  input.
- **Local-storage signed URLs were hardened.** They now sign the download name and
  content type as well as the key, with a key derived for that purpose. Every download
  is forced to `attachment` with `nosniff` and a sandbox CSP, so an uploaded HTML or
  SVG file cannot run on the application's origin.
- **Home opens My tasks** for anyone who can update tasks but not read deals, such as
  developers.

## Scope

In:
- Projects, optionally tied to a client and a won deal, with statuses, dates, budget,
  owner, and archive/restore.
- Members with role and rate overrides.
- Milestones with completion.
- Tasks with assignee, priority, status, due date, labels, estimate, milestone, and
  dependencies with cycle detection.
- Derived progress.
- Comments and project updates.
- Attachments on tasks and projects.
- `client_visible` on milestones, tasks, comments, and attachments.
- The projects list, project page (tasks board, milestones, team, updates, files,
  details), task page, My tasks page, and the client view's Projects section.

Out:
- Time entries (S6). Deleting a task that has time logged against it will need a rule then.
- Recurring tasks, Gantt charts, and per-role project visibility, such as developers
  seeing only their own projects (Phase 2).
- Editing `client_visible` on an existing attachment (it is set at upload).
- Sweeping storage for orphaned files (S10).

## Notes for later slices

- **S6 time entries** should reference tasks with `(organization_id, project_id,
  task_id)` composite keys, as dependencies do. `task.delete` will need to refuse, or
  detach entries, once time is logged.
- **Rate resolution order** (S6): the project member override, then the person's
  default, then the organization's default. Copy the result onto the entry.
- **`ctx.afterCommit` failures are logged, not thrown**, because the change has already
  happened. Never put something there whose failure must fail the request.
- **Server Actions accept 21 MB bodies** (`next.config.ts`) because attachments go up to
  20 MB. A reverse proxy in front needs the same, for example
  `client_max_body_size 21m` in nginx.
- **An aliased table inside a raw `sql` template loses its alias.** Write the
  subquery with plain table names, as `openDependencies` does.
- **Uploads through the API and Server Actions arrive as `File`**, validated with
  `z.file()`. The idempotency hash includes each file's name, size, and type, not its
  bytes.
- **Signals do not pass through `pnpm exec` or `pnpm run`.** Stopping the pnpm
  process leaves the app and worker running as orphans. This explains the
  workers that seemed to ignore SIGTERM during S4's test runs: the worker itself shuts
  down cleanly when signalled directly. S10's container images must start `node` (or
  `tsx`) as the main process, not pnpm, or `docker stop` will wait out its timeout and
  kill the worker mid-delivery.
