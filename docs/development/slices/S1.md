# S1 — Identity & tenancy

**Depends on:** S0
**State:** done

**Amends the plan:**

- **Better Auth has no API key plugin** (1.7.3), and `@better-auth/api-key` is
  not published. API keys are hand-rolled in `packages/core` and
  `packages/auth`. This turned out to be the better design regardless: the
  behaviour that matters — a key's permissions intersected with its owner's
  *live* role — is custom either way.
- **UUIDv7 works with Better Auth's tables** in native `uuid` columns via
  `advanced.database.generateId`. The plan's fallback (text ids for auth tables)
  was not needed. Node has no native v7 — `crypto.randomUUID({ version: 7 })`
  silently returns a v4 — so ids come from the `uuid` package.
- **API key lookup uses a flag-gated policy, not `SECURITY DEFINER`.** The
  definer function fails under `FORCE ROW LEVEL SECURITY`, because its owner is
  the application role. See [Architecture](../../architecture.md#authenticating-api-keys).
- **Email verification was added**, and is required to accept an invitation.
  Signing in does not require it, so a self-hoster whose SMTP is not yet working
  can still reach their own install.
- **`next lint` no longer exists in Next 16.** Lint runs `eslint .` at the root.
- **UI primitives are hand-written** in `packages/ui` in the shadcn style rather
  than generated by the shadcn CLI. S1 needs forms and tables; the CLI and its
  Radix dependencies arrive when a slice needs dialogs or menus.
- **Idempotency keys move to S2.** No S1 mutation is money-bearing, and S2 is
  where external automation first calls in — which is what idempotency protects.
- **`MAIL_DRIVER=memory`** exists so tests exercise real invitation and
  verification flows without an SMTP server. It is rejected in production.

## Scope

In: sign-up, sign-in, password reset, email verification; organizations and the
active-organization session; invitations and acceptance; roles and the
permission matrix; `resolveActor` and `ActorContext`; RLS policies for S1's
tenant tables; the audit log, including Better Auth's membership events; the
procedure registry; the REST API and generated OpenAPI; API keys; rate limiting;
transactional email; settings UI for organization, members, API keys, and the
audit log.

Out: webhooks and events (S2); idempotency keys (S2); SSO and custom roles
(Phase 2); teams (not planned).

| 7 | `next build && NODE_ENV=production next start`, then `pnpm test:e2e` | exit 0 — sign-up, organization, settings audit, invite → verify → join, scoped API key. **Against a production build**, not only `pnpm dev` |

| 9 | Demote a key's owner, then call `GET /api/v1/me` with the key | permissions shrink with no key change (`packages/auth/test/api-keys.test.ts`) |
| 10 | Org B's owner revokes org A's key by id | `NotFoundError`, key untouched (`packages/core/test/procedures.test.ts`) |
| 11 | Add a mutation to the registry without an audit fixture | `procedures.test.ts` fails |
| 12 | A client component imports `@workloom/auth` | lint error |

Checks 5, 9, 10 and 11 are the safety properties. Checks 6 and 7 exist because
of two bugs that every other check missed:

- a client component pulled nodemailer and `pg` into the browser bundle, which
  the dev server reported only as a missing `build-manifest.json`;
- the procedure registry threw on re-registration in production, where Next
  evaluates shared modules once per route bundle. Every settings page returned
  500 in production while unit, integration, isolation, and dev-server E2E runs
  were all green.

The `build-and-e2e` CI job runs the production build for this reason.

## Notes for later slices

- **Add procedures, not routes.** A `defineProcedure` call gives the REST
  endpoint, OpenAPI entry, and permission check. Then add its fixture to
  `MUTATIONS` in `packages/core/test/procedures.test.ts`, or the suite fails.
- **User-facing rule violations throw `DomainError`.** A plain `Error` becomes a
  500 with its message withheld.
- **Every new tenant table needs its policy in a hand-written migration**
  (`drizzle-kit generate --custom`), in the `nullif` form. The isolation suite
  fails until it exists.
- **``tx.execute(sql`…`)`` returns strings for timestamps and numerics.** Prefer
  the typed query builder; parse explicitly when raw SQL is unavoidable.
- **Better Auth endpoints bypass the registry.** Anything reachable at
  `/api/auth/*` must be checked there too. The last-owner and owner-escalation
  rules currently hold on that path through Better Auth's own checks, pinned by
  `membership.test.ts` and `escalation.test.ts` so an upgrade cannot quietly
  remove them.
- **Pages call `call(procedure, input)`** from `apps/web/lib/server/procedures.ts`.
  Client components receive data as props and never import server packages.
- **Next 16 reminders:** `params`, `searchParams`, `cookies()`, and `headers()`
  are async-only; `middleware` is now `proxy`; `revalidateTag` takes two
  arguments. `apps/web/AGENTS.md` points at the version-matched docs.
- **Running `next typegen` while `next dev` is running corrupts `.next`.** Stop
  the dev server first, or delete `apps/web/.next` afterwards.
