# S3 — CRM

**Depends on:** S1, S2
**State:** done

**Amends the plan:**

- **The spec's single pipeline is split at qualification.** Spec §6.2 describes one
  pipeline: New Lead → Contacted → Qualified → Proposal Sent → Negotiation → Won / Lost.
  Before qualification a prospect is a **lead**, with status `new`, `contacted`,
  `qualified`, or `disqualified`. After it they are a **deal**, with stage
  `qualified`, `proposal_sent`, `negotiation`, `won`, or `lost`. Conversion is the
  hand-off. Leads stay in their own table as the plan intended: enquiry forms and the
  API produce rows that must not clutter the company list.
- **A client is a company whose `lifecycle_stage` is `client`**, as planned. Companies
  become clients when a deal is won, when a lead is converted **without** a deal, or
  when someone sets the stage. `former_client` exists for relationships that lapse.
- **Notes are activities.** The spec lists Activity and Note separately. One
  `activities` table has types `note`, `call`, `email`, and `meeting`.
- **The catalogue gained** `*.updated`, `*.archived`, and `*.restored` for leads,
  companies, contacts, and deals, plus `activity.logged`, `activity.updated`, and
  `activity.deleted`. Without them an integration syncing contacts to another tool
  would have to poll.
- **A small currency module arrived early** (`packages/core/src/money/currency.ts`):
  ISO 4217 exponents and exact string-based parsing and formatting. Deal values need
  it now; S7a builds the rest of the money primitives on it.
- **The home page opens the pipeline** for anyone who can read deals, instead of
  organization settings.

## Scope

In:
- Companies, contacts, leads, deals, and activities: schema, row-level security,
  procedures, REST, and UI.
- Lead status changes and lead conversion.
- Deal stages, including won and lost, and the pipeline board with per-currency totals.
- Archive and restore for every CRM record.
- Activity timelines with permission-aware visibility.
- Main navigation.
- Events for every mutation.

Out:
- The unified client page with tabs for projects, invoices, and so on (S4).
- Configurable pipelines, custom fields, tags, and duplicate merging (Phase 2).
- Web-to-lead capture forms (Phase 2; the REST API already accepts leads).
- Deal value conversion into the base currency (needs S7's exchange rates).
- Import and export (S10).
- A cross-record activity feed (S9 dashboard).

## Notes for later slices

- **Every new mutation still needs a fixture in `procedures.test.ts`.** A fixture
  may now be a list: when a mutation's events depend on its input (won *or* lost),
  list one fixture per outcome. Together they must emit every declared event, and
  none may emit an undeclared one.
- **The cross-tenant probe is generated.** Any fixture whose input carries `id`,
  `companyId`, `contactId`, `leadId`, or `dealId` is replayed as another
  organization and must raise `NotFoundError`. Add new reference keys to
  `REFERENCE_KEYS`. Every read with a path parameter needs an entry in `READS`.
- **Links between tenant tables are composite foreign keys** on
  `(organization_id, id)`. Copy the pattern in `packages/db/src/schema/crm.ts`.
- **Status vocabularies live in the schema file** (`LEAD_STATUSES`, `DEAL_STAGES`,
  and so on) as literal CHECK lists. Core imports them for validation, so there is one
  definition. Adding a value takes a migration that replaces the CHECK constraint.
- **Money over the API is an integer count of minor units** (`valueMinor`) with its
  `currency`, bounded to 2^53 − 1. Forms parse "12,500.50" with `parseAmount` in the
  Server Action; nothing parses money with `Number` or `parseFloat`.
- **An activity is only as visible as every record it is linked to.** A note on a deal
  also carries the deal's company, and someone without `deal:read` does not see it on
  the company either. Converted leads keep `lead_id` on their activities, so their
  pre-conversion history stays hidden from roles without `lead:read`, including
  developers. S4 should decide whether that is right for the client page.
- **Lists page by UUIDv7, newest first.** The activity timeline is ordered by
  `occurred_at` instead, so its cursor is opaque rather than an id.
- **React resets a form after its action returns**, including when validation fails.
  CRM actions return the submitted values in `ActionState.values`, and the fields in
  `components/crm/fields.tsx` fill themselves from them. Use those fields.
- **Actions that change the active organization must call
  `revalidatePath('/', 'layout')`.** A redirect alone keeps the layout rendered for
  the previous organization, which left the switcher and navigation missing after
  creating an organization. This bug dated from S1.
- **Don't build lists of time zones, locales, or similar in client components.** Node
  and browsers ship different ICU data, and the organization settings page failed to
  hydrate because of it (fixed here).
