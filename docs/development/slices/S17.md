# S17 — Project billing models, types, and budgets that speak up

**Depends on:** S5 (projects), S6 (time), S8 (profitability), S15 (expense cost)
**State:** done

**Amends the plan:**

- **A project says how it is paid for.** `projects.billing_model` is
  fixed price, retainer, time and materials, or not billed. Existing projects
  were backfilled: a contract value means fixed price, no client means not
  billed. A retainer cannot have a contract value; a fixed price budgets over
  the whole job. Both are refused by the procedures and the database.
- **Project types are the agency's own** (`project_types`): "Web development",
  "Web development + maintenance", "Digital marketing", "Support and
  maintenance" to start, each with the billing model and budget period a new
  project takes. Projects keep their own settings when a type changes.
- **Budgets can be per period and in hours.** `budget_period` (whole project,
  week, month, quarter, year) and `budget_hours`; without an hours budget, a
  whole-project budget is measured against the tasks' estimates.
- **Over-budget projects are surfaced, not sought** (US-10). An hourly sweep
  records each threshold (80%, 100%) a project crosses, once per budget period
  (`project_budget_alerts`), emits `project.budget_threshold_crossed`, audits
  it, and emails the project's owner. The dashboard lists projects at risk.
- **The worker now runs a sweep's after-commit work.** Before, a context built
  for a sweep collected `afterCommit` hooks that nothing ran.

## Scope

In:
- `projectType.list|create|update`, `project.budget`, `report.projectBudgets`;
  project create/update take a type, billing model, hours budget, and period.
- The project form, a Budget card on Financials, kind and billing model on
  the projects list, "Projects at risk" on the dashboard, Settings → Project
  types.

Out:
- An immediate alert as time is logged (the hourly sweep covers it).
- Per-milestone budgets.
