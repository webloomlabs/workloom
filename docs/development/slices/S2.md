# S2 — Outbox, events, webhooks

**Depends on:** S1
**State:** done

**Amends the plan:**

- **No pg-boss, and no `packages/jobs`, yet.** The plan made pg-boss the default
  queue. Webhook delivery needs only a retry schedule, and the delivery table can
  carry that itself (`next_attempt_at` plus a lease), which makes the delivery log
  the queue rather than a view of one. A general job queue arrives with the first
  slice that needs one (likely S7b: PDF rendering and invoice email). Redis remains
  optional; nothing here uses it.
- **The dispatcher uses a flag-gated policy** (`workloom.dispatcher`), not
  per-organization enumeration. Polling every second would otherwise mean one query
  per organization per second. Same pattern as S1's `auth_lookup`, lint-confined to
  one file. See [Architecture](../../architecture.md#flag-gated-policies).
- **Polling, not `LISTEN/NOTIFY`.** The plan listed NOTIFY as a latency optimisation.
  It is deferred: polling is the correctness floor and a one-second latency is fine
  for webhooks.
- **Redirects are never followed** (the plan said re-check after redirects). A
  redirect is an unverified second destination; refusing it is simpler and stricter.
- **The event catalogue gained** `organization.updated`, `member.role_changed`,
  `member.removed`, and `invitation.cancelled`, and declares every event through S7
  so integrations can subscribe ahead of the modules.
- **Idempotency keys**, moved from S1, landed here as planned — scoped per actor as
  well as per organization, which the plan did not specify.
- **A cross-origin check for cookie-authenticated API writes** was added. It closes a
  gap present since S1, previously covered only by the session cookie's `SameSite=Lax`.

## Scope

In: the outbox and `ctx.emit`; the frozen event catalogue; event emission from every
S1 mutation and Better Auth membership hook; webhook endpoints, signing, secret
encryption and rotation; the worker's publish and deliver loops with retries, leases,
and auto-disable; SSRF protection; idempotency keys; the webhooks UI and delivery log;
the webhook receiver guide.

Out: manual replay of *successful* deliveries and payload inspection beyond the
response log (Phase 2); `LISTEN/NOTIFY`; event retention and pruning of old events and
deliveries (S10); moving transactional email onto the outbox (with the job queue).

## Notes for later slices

- **Declare `emits` on every new mutation**, and call `ctx.emit` with the entity's REST
  representation. Never include secrets: events fan out to third-party URLs.
- **A no-op update emits nothing.** Fixtures that repeat an update must change
  something each time, or the event coverage test reads it as a missing event.
- **Adding an event type:** add it to the catalogue with its `since` slice. Never rename
  or remove one.
- **The worker must run for webhooks to deliver.** In development: `pnpm worker`. It
  refuses to start as a database superuser, like the app.
- **Local webhook testing** needs `WORKLOOM_ALLOW_PRIVATE_WEBHOOKS=true` on both the app
  and the worker. Never in production.
- **Partial-index predicates need `sql` literals.** `eq()` emits a bind parameter, which
  is invalid in index DDL; drizzle-kit generates the broken migration without complaint.
- **`defineProcedure` paths must not collide** with a parameterised sibling:
  `/webhooks/event-types` would be captured by `/webhooks/{id}`. Hence
  `/webhook-event-types`.
- **Page files may only export Next's conventions.** Shared components go in
  `apps/web/components`, not in a `page.tsx` another page imports.
