# S19 — Receipts from Telegram, read by AI

**Depends on:** S15 (expenses, receipts, drafts)
**State:** done

**Amends the plan:**

- **One bot per organization, brought by the organization** (`telegram_bots`):
  the token from @BotFather, encrypted at rest. The bot that receives a message
  is what says which organization it is for.
- **Messages land in an inbox first** (`telegram_updates`), from a webhook
  (`POST /api/integrations/telegram/<org id>`, checked by a per-bot secret
  header) or from the worker polling Telegram. The worker handles the inbox
  every few seconds, outside any transaction, with a lease and retries. The
  unique key on Telegram's update id makes a double delivery one expense.
- **People link themselves** with a one-time code (`messaging_link_codes`,
  hashed, ten minutes) sent as `/start <code>`; the link
  (`messaging_identities`) ends when they are unlinked or leave the
  organization.
- **A photo or PDF from a linked member becomes a draft expense**, made as them
  through `expense.createFromReceipt`, with the receipt attached. The bot
  replies with Confirm and Discard buttons; a press runs `expense.confirm` or
  `expense.delete` as whoever pressed it, with their permissions.
- **Reading receipts with AI is the organization's switch**
  (`organization.receipt_reading_enabled`, off by default). The installation
  chooses the provider by its key: Anthropic Claude, OpenAI, Google Gemini, or
  Groq (`RECEIPT_PROVIDER` when several are set, `RECEIPT_MODEL` to change the
  model). `@workloom/ai` holds one reader per provider, each on its official
  SDK (Groq through its OpenAI-compatible endpoint), all sharing one prompt and
  one JSON schema, so core never depends on an SDK. Groq's vision models take
  photos only; a PDF there is stored unread.
  What it reads is checked by `normaliseReading` -- amounts parsed exactly,
  no future or ten-year-old dates, only the organization's categories -- and
  only ever fills a draft. A failure leaves the draft blank. What was read is
  kept on the inbox row, so a retry never reads twice.
- **Audit entries say which door a change came in by** (`audit_logs.source`:
  web, api, telegram, worker, system).
- The expense form gains **Start from a receipt**, which uses the same path.
- **Groups**, added after: `telegram_groups`, approved by an owner or admin
  with a one-time group code (`telegramGroup.createLinkCode|list|revoke`, link
  codes now carry a `purpose`). In an approved group a linked member's receipt
  becomes their draft, with the details sent privately; the bot is silent in
  any other group and to anyone not linked. Removing the bot from the group
  ends the approval, and a group that becomes a supergroup keeps it.

## Scope

In:
- `telegramBot.connect|get|update|disconnect`,
  `messagingIdentity.createLinkCode|list|revoke`, `expense.createFromReceipt`;
  `organization.update` takes `receiptReadingEnabled`.
- New permission `integration:manage` (owners and admins).
- Worker: Telegram polling and inbox processing.
- Web: Settings → Telegram (connect, mode, pause, link my Telegram, linked
  people, reading receipts); Start from a receipt on New expense.

Out:
- Editing an expense from the chat (the reply links to it instead).
- More than one bot per organization.
- A QR code for the link (the deep link opens Telegram directly).

## Definition of done

1. `pnpm vitest run --project unit packages/core/src/modules/finance/receipt-extraction.test.ts packages/core/src/modules/integrations packages/ai` passes (each provider's reader against a local stand-in for its API).
2. `pnpm vitest run --project integration packages/core/test/telegram.test.ts packages/core/test/procedures.test.ts` passes, against a fake Telegram and a fake reader.
3. `pnpm test:isolation` passes, with the four new tables under row-level security.
4. `pnpm openapi:check` passes.
5. `pnpm --filter @workloom/e2e test specs/receipts.spec.ts` passes against a running instance.
6. By hand: connect a real bot, link your account, send a receipt photo, confirm it from the chat, and see the expense and receipt in Workloom.
