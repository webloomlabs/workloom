# S0 — Platform skeleton

**Depends on:** nothing
**State:** done

**Amends the plan:**

- **Next 16, not 15.** The plan assumed Next 15; 16 is current and the App
  Router architecture is unchanged. Two differences bit during S0:
  `experimental.serverComponentsExternalPackages` is now `serverExternalPackages`,
  and `next dev` refuses to run twice against the same directory.
- **React pinned to 19.2.8.** The workspace enforces a minimum release age on
  dependencies, and 19.3.0 was published inside that window.
- **A single root `.env`.** Next loads `.env` from the app directory, but the
  web app, worker, and CLI are three entrypoints into one installation, and
  asking a self-hoster to maintain three files would be a poor trade for our
  internal structure. `packages/config` walks up to the workspace root and
  loads it, without overriding real environment variables.

## Scope

In: monorepo and tooling, CI, dev services, Drizzle wiring, migrate-on-boot,
environment schema, health endpoint, storage package, app shell, and the
tenant-isolation harness.

Out: anything with a user in it. Identity, organizations, and the procedure
registry are S1.

## Definition of done

| # | Check | Expected |
| --- | --- | --- |
| 1 | `pnpm typecheck` | exit 0 across all packages |
| 2 | `pnpm lint` | exit 0 |
| 3 | `pnpm test:isolation` | exit 0, and **not** vacuous — includes a canary test that creates an unprotected table and asserts it is reported |
| 4 | `pnpm services:up && pnpm dev` | logs `boot: migrations up to date` and `boot: tenant isolation verified` |
| 5 | `curl localhost:3000/api/health` | `200` with `{"status":"ok"}` |
| 6 | Boot with `DATABASE_URL` pointing at a superuser | process **exits**, naming the role and the consequence |
| 7 | Import `db` from `@workloom/db` outside the allowlist | lint error |

Checks 3, 6 and 7 are the ones worth keeping honest. The others confirm the
scaffolding runs; those three confirm the safety properties actually hold.

## Notes for later slices

- The isolation checks are introspective, so they already cover the tables S1
  will add. Adding a tenant table without a policy will fail CI immediately —
  that is intended, not a bug in the harness.
- `packages/db/src/migrations/meta/_journal.json` is an empty journal. The
  first real migration arrives with S1.
- `pg` is configured to return `int8` as a string. Do not "fix" this: it is
  what stops every monetary value from silently losing precision above 2^53.
- The `withoutTenant` caller table in `docs/architecture.md` is empty. Keep it
  that way for as long as possible.
