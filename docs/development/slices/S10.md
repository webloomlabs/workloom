# S10 — Release hardening

**Depends on:** every slice before it
**State:** done

**Amends the plan:**

- **The production images and `docker-compose.yml` are built here, not in S0.**
  S0 shipped `docker-compose.dev.yml` for the backing services and left the
  application running on the host. Nothing since needed an image, and the
  clean-install CI job carried a stub comment saying so. Self-hosting is exit
  criterion 3, so the image is this slice's first job rather than its last.
- **Export is a catalogue, not a reflection over the schema.** A CSV someone
  opens in a spreadsheet is a contract: columns must not move because a
  developer renamed a field. Each exportable resource names its columns
  explicitly, and a test asserts the header line, so a change to one is a
  decision rather than an accident.
- **`apps/cli` is not built.** The plan sketched a `workloom` admin CLI for
  create-org, invite, rotate-key and export. Every one of those is reachable
  through the API with a key, and the empty directory is removed rather than
  left as a promise. Noted for Phase 2.
- **The OpenAPI document is committed, and CI fails if it drifts.** The plan
  asked for an `openapi-diff` job against the last tag; before a first tag there
  is nothing to diff against, so the snapshot in the repository is the baseline.
  It turns a breaking API change into a visible diff in review.
- **Backup and restore are scripts that were actually run**, against a database
  with real rows, and the transcript is in the documentation. A backup procedure
  nobody has restored from is not a backup procedure.

## Scope

In:
- `docker/Dockerfile.web`, `docker/Dockerfile.worker`, and a production
  `docker-compose.yml` that brings up a working installation from a clean
  checkout and a copied `.env`.
- CSV export for every resource an agency would want out of the system.
- The OpenAPI document committed and checked in CI, and documented as a product
  surface.
- The documentation tree of spec §35.
- `scripts/backup.sh` and `scripts/restore.sh`, executed and written up.
- The lifecycle browser test the roadmap names as exit criterion 2, in one run.
- A security pass, written down, with anything it found fixed.

Out:
- The `workloom` admin CLI (Phase 2; every operation is in the API).
- Publishing images to a registry, and any hosted deployment.
- Localisation, theming, and anything else not named in the exit criteria.
- Creating the `v0.1` tag itself, which is the maintainer's to make on a commit.

## What this slice found

- **Nothing had ever built the production images.** S0 shipped the backing
  services and left the application on the host, and every slice since had no
  reason to notice. Four real deployment bugs came out of building them, none of
  which any test could have caught:
  1. **The font files never reached the image.** They are data, not modules, so
     tracing did not carry them — and `new URL('../fonts', import.meta.url)` made
     the bundler try to resolve a directory as a module. Resolved through
     `WORKLOOM_FONT_DIR`, which the image sets, and it now throws a message
     naming the variable rather than rendering blank boxes.
  2. **The migration files never reached it either**, so the application booted
     against whatever schema was there. Same resolution, `WORKLOOM_MIGRATIONS_DIR`.
  3. **The uploads volume belonged to root** while the container ran as uid 1001,
     so every attachment failed with `EACCES`. Docker seeds a named volume from
     the image's directory, ownership included, so the image now creates and owns
     it. Found by running the browser suite against the containers.
  4. **The worker could not resolve its own workspace packages**: pnpm puts a
     `node_modules` of symlinks inside each package, and only the root one had
     been copied.
- **`.dockerignore` did not exist**, so the build context was carrying
  `node_modules`, `.next`, `.git` and the developer's real `.env`.
- **The security pass found three things** — no response headers at all, eleven
  nodemailer advisories, and a worker image shipping its whole build toolchain.
  All three are fixed; `docs/security.md` records them and the two dev-only
  advisories that remain, with the reason each is not exploitable here.
- **A `.env` edit for one test run broke another suite.** Setting
  `WORKLOOM_ALLOW_PRIVATE_WEBHOOKS` in `.env` to exercise the composed stack also
  disabled the SSRF guard the integration tests assert. The compose file now
  takes it from the shell instead, so a test run never has to edit `.env`.
- **The webhook browser test could not reach a containerised worker**, because
  its receiver bound to loopback. It now takes `E2E_RECEIVER_HOST`, which is what
  lets the whole suite run against the composed installation rather than only
  against a host process.

## Notes for later slices

- **Phase 2's client portal** reuses the client-visible flag and the signed-link
  pattern from S7b.
- **The admin CLI**, if it is ever wanted, should be a thin API client rather
  than a second way into the domain.
- **A nonce-based Content-Security-Policy** needs middleware on every request.
  The current policy allows inline scripts, which Next hydrates through; what it
  buys today is that nothing loads from another origin.
- **The licence is still unset.** `README.md` says so. It is the maintainer's
  decision and blocks the tag, not the code.
